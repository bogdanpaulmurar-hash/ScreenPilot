# Release 0.7.5 — MP4 with Windows' own encoder; drawing tools while recording

## User release notes
- **MP4 recordings no longer need FFmpeg.** Video without sound is now written by the H.264 encoder built into Windows, inside ScreenPilot. Security software that blocks or stops `ffmpeg.exe` can no longer interrupt a recording.
  - *Settings › Recording › Video engine*: **Automatic** (default: Windows for video, FFmpeg when sound is on), **Windows**, or **FFmpeg**. The line below it says whether the Windows encoder works on this PC.
  - Sound (microphone / system audio) still needs FFmpeg. When FFmpeg is missing or was stopped during a recording, ScreenPilot records video without sound with the Windows encoder.
  - No more "trying another encoder" loop where the recording stopped, an error showed and the frame came back.
- **Drawing while recording**: the toolbar buttons (rectangle, arrow, highlight, steps…) can be clicked again while drawing is on. Before, the drawing layer covered the toolbar, so each click placed a step number instead of choosing the tool.
- `record-info` shows whether the Windows encoder is available.

## Technical release notes
- New `recording/mediafoundation.py`: `MediaFoundationSink` (same protocol as `FfmpegSink`) over the Media Foundation Sink Writer, called through ctypes COM vtables (no new dependency).
  - The owner thread runs in the COM MTA with `MFStartup`; hardware transforms are enabled; the input is RGB32 with a positive stride (top-down BGRA frames).
  - Each frame's duration runs to the next timestamp; there is a bounded queue (30 frames), and frames are dropped (and counted) instead of blocking capture.
  - `bitrate_for()` maps quality to a bitrate (0.5–50 Mbit/s).
  - `availability()` test-encodes a 64×64 clip once and caches the result. It is warmed up on a background thread after start-up.
- `RecordingOptions.engine` / setting `recording.engine` (auto, windows, ffmpeg).
- `RecordingService.choose_engine()` and the injectable `windows_encoder`. `ffmpeg_unreliable` is set after an `encoder_failed`.
- The UI encoder retry goes to the Windows encoder and never retries the Windows encoder itself.
- `InkOverlay(blocked=...)` ignores presses over the recording bar; `RecordingController._keep_bar_on_top()` re-raises the bar after the overlay is shown and while drawing.
- ADR-21. CI prints Media Foundation availability; the real-encoder test skips where Media Foundation is missing (Windows Server without the feature).
