# Release 0.7.6 — scrolling capture works again; manual scrolling mode

## User release notes
- **Scrolling capture no longer stops after the first frame.** It used to stop with "The page changed while scrolling" in browsers and grids. There were three causes:
  - The selection overlay was sometimes still on screen when the first frame was taken. ScreenPilot now waits until the view is still before it starts.
  - The row under the mouse cursor changes colour (hover highlight) while the page moves. Those rows are now left out of the comparison.
  - Small rendering differences after a scroll (anti-aliasing, smooth scrolling still running). Frames are taken once the page has stopped moving, and matching tolerates small differences.
- **Manual mode** (*Settings › Capture › Scrolling capture*):
  - **Automatic** (default): ScreenPilot scrolls for you.
  - **Manual**: you scroll yourself, with the wheel, keys or scrollbar, at your own pace. Press Esc when you are done.
  - In manual mode, if you scroll too far at once, scroll back a little and the capture picks up again.

## Technical release notes
- `scrolling.grab_stable()`: grabs until two consecutive frames are identical, with a time limit.
  - First frame: 0.3 s initial wait, then grabs 0.25 s apart, up to 1.5 s.
  - After each scroll: grabs 0.1 s apart, up to 1.2 s.
  - The `settle` argument keeps the old fixed wait (used by tests).
- Tolerant fallback when the exact row match fails:
  - `row_profiles()` reduces each row to (sum of sampled green values, number of dark samples).
  - `find_shift_fuzzy()` picks the shift where most informative rows agree (≥ 75 %). It first checks for an unchanged view (shift 0).
  - A band around the parked cursor row is ignored. Repeating content prefers the previous shift.
  - Sticky header/footer detection uses the same tolerance.
- `capture_scrolling_manual()`: polls every 0.15 s, skips frames it cannot match, and stops on Esc (`done`), at 300 s (`timeout`) or at `max_height`.
  - `CaptureService.capture_scrolling(manual=...)` and the setting `capture.scroll_mode` (auto | manual).
  - In manual mode the cursor is not moved back at the end.
- Logs report the number of tolerant matches and skipped frames.
