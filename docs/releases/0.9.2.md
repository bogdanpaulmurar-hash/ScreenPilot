# Release 0.9.2 — OK button for scrolling capture

## User release notes
- **OK on the scrolling pill**: while a scrolling capture runs (automatic or manual), the progress pill next to the area has an **OK** button. A click finishes the capture and keeps what was captured, with no question. Useful when Esc does not reach ScreenPilot because the app being captured uses it.
- **The captured app keeps the keyboard**: clicking OK never activates ScreenPilot or moves the focus away from the app being scrolled.
- **Not in the picture**: the pill stays outside the area (below it, or above it when there is no room) and is hidden from screen capture on Windows 10 2004 and later.
- **Automatic mode waits while the mouse rests on the pill**, so the cursor is not pulled back into the area while you aim at OK.
- Esc works as before: automatic mode pauses and asks, manual mode finishes.

## Technical release notes
- `capture.scrolling.capture_scrolling(finish=, hold=)` and `capture_scrolling_manual(finish=)`: `finish()` ends with reason `stopped` (`done` in manual mode) without calling `on_stop`; while `hold()` is true no scroll is sent. `CaptureService.capture_scrolling` drops `hold` in manual mode.
- `ui.preview.ScrollIndicator`: no longer transparent for input; painted OK button (`ok_rect()`, `finish()`, `finish_requested`), `hovered` / `finished` `threading.Event`s read by the worker; acts on mouse press; placed above the region when there is no room below.
- `platform.win32_window.set_no_activate()` (`WS_EX_NOACTIVATE`) and `exclude_from_capture()` (`SetWindowDisplayAffinity`).
- i18n: `scroll.ok`, `scroll.ok.tooltip`, `scroll.finishing`; progress texts mention OK (EN + RO).
- Tests: `OkButtonTests` (headless: finish, Esc still works, hold, manual finish, service) and three `ScrollingUiTests` (OK click, click beside OK + hover hold, manual mode).

## Checklist (Windows)
- [ ] Automatic scrolling in a long page (Excel, browser): click OK on the pill; the capture stops at once, is kept, no question appears.
- [ ] While it scrolls, the app being captured stays active (title bar does not grey out); after OK, typing goes to that app without clicking it.
- [ ] Rest the mouse on the pill during automatic scrolling: scrolling waits; click OK: it finishes.
- [ ] Manual scrolling (Settings › scroll mode manual): scroll by hand, click OK; the capture is kept.
- [ ] The saved image never contains the pill, also with an area that reaches the bottom of the screen.
- [ ] Esc still works: automatic mode pauses and asks, manual mode finishes.
