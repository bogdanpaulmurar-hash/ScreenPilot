# Release 0.4.0 — Smart capture

## User release notes

**New**
- **Automatic frame detection**: in the selector, the field, button, panel or dialog under the mouse is outlined automatically. Click to capture just that frame. **Mouse wheel / Tab** moves out to the parent frame, up to the whole window.
- **Scrolling capture** (long screenshots):
  - in the selector: select an area, press **S** (or the scroll button) — ScreenPilot scrolls and stitches;
  - **Ctrl+Shift+6**, the hub *Scrolling* tile or the top edge bar;
  - Samsung style: on the quick preview, **Capture more ↓** continues downwards.
  - Sticky headers/footers appear once; it stops by itself at the end of the page; **Esc** stops it earlier.
- **Number steps** on a capture: press **N** in the selector (or *Number steps* on the preview / in History). Click the elements of a procedure in order — 1, 2, 3 are placed automatically, attached to the element and highlighted. Drag to move, right-click to delete (the rest renumber), Ctrl+Z to undo, choose colour, size, shape and start number.
- **History size** is a setting (default 100).

**Tips**
- Any shortcut can open the selector — e.g. set *Capture region* to **Ctrl+Space** or **PrintScreen** in Settings › Shortcuts; then choose in the action bar: normal (Enter), scrolling (S), steps (N), copy (Ctrl+C), pin (P).

**Known limitations**
- Scrolling capture moves the mouse into the area while it scrolls (it is put back afterwards).
- Pages that animate or lazy-load while scrolling can stop the capture early (you get the part captured so far).
- Frame detection works on visible lines; borderless designs fall back to the whole window.

## Technical release notes
- `capture.detect` (edge maps, line/corner checks), `SelectionModel` frame levels, Win32 child windows.
- `capture.scrolling` (row-signature stitcher, sticky band detection, anchor voting), `capture.win32_scroller` (SendInput wheel, Esc via GetAsyncKeyState), `CaptureService.capture_scrolling`.
- `editor.steps` (StepDocument, render_steps), `ui.step_editor`.
- New setting `history.limit`; new default hotkey `capture.scrolling = Ctrl+Shift+6`.

## Test checklists

### Smoke (5 min)
- [ ] Ctrl+Shift+1, hover a text field in any app: only the field is outlined; wheel up: the parent panel, then the window.
- [ ] Select a browser page area, press S: a long image is produced and saved.
- [ ] Ctrl+Shift+1 on a form, press N, click 3 fields: badges 1-2-3 appear; Done copies the result.

### Functional (15 min)
- [ ] Scrolling capture on: Chrome/Edge page, an Excel sheet, an ERP grid, a long settings page.
- [ ] Page with a sticky header (e.g. GitHub): the header appears only once.
- [ ] Esc during scrolling stops it and keeps what was captured.
- [ ] Preview › Capture more ↓ extends a normal capture.
- [ ] Steps: delete step 2 → 3 becomes 2; Ctrl+Z restores; change colour and size.
- [ ] Settings › General › Captures kept in history: set 20; the history keeps the 20 newest.

### Full validation
- [ ] 150 % scaling: frames and scrolling are pixel-exact.
- [ ] Classic Win32 app (e.g. an old ERP client): child controls are offered as frames.
