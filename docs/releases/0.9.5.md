# Release 0.9.5 — Scrolling capture: floating boxes and blinking carets

## User release notes
- **Fixed**: scrolling capture of apps with a floating input box over the page (chat windows such as the Claude panel in VS Code) pasted the box into the picture at every step. The box now appears once, at the end.
- **Faster**: a blinking text caret no longer keeps the capture waiting for the view to "stand still" after every scroll.

## Technical release notes
- `capture.scrolling.tail_overlay()`: after the scroll shift is voted by unique rows, the rows that disagree between the two frames form one block that ends where the compared range ends: the previous frame's floating box. Its height is added to the sticky bottom (remembered in `ScrollStitcher._footer`, re-checked every frame), so it is neither compared nor pasted again. Order in `ScrollStitcher.add`: remembered box → strict match → box detection → hover-only match (0.9.4) → tolerant profile match.
- `find_shift(..., hover=False)` for the strict pass.
- `frames_close()` / `grab_stable()`: two grabs that differ only within `CARET_MAX_PX` pixels per row count as identical (a blinking caret never made two grabs equal, so every step waited for the 1.2 s limit).
- Tests: `FloatingBoxScrollingTests` (automatic and manual, several box sizes, blinking caret) and caret tests; seven of them fail on 0.9.4.
- Limitation: with very little visible page above the box (a step larger than the visible area, long blank stretches) the capture can still stop with "page changed".
