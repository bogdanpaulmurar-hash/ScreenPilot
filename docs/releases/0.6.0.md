# Release 0.6.0 — Draw on your recordings

## User release notes

**Annotations while recording (MP4 and GIF)**
- New **pen** button on the recording bar. Turn it on and draw directly on the recorded area:
  - **numbered step**: click (1, 2, 3… automatically);
  - **arrow**, **rectangle**, **highlight**: drag;
  - **text**: click where it should go, type, Enter.
- Everything you draw is in the video right away, exactly where you drew it. No editing afterwards.
- While the pen is on:
  - keys **1–5** pick the tool (step, arrow, rectangle, highlight, text);
  - **Ctrl+Z** or **right-click** undoes the last annotation;
  - **Delete** removes them all (step numbers continue);
  - **Esc** puts the pen away. A second Esc pauses the recording, as before.
- With the pen off, the mouse works normally in the recorded app and the annotations stay visible.
- **Settings › Recording › Annotations while recording**:
  - **Annotation colour**;
  - **Annotations disappear**: never, or after 3 / 5 / 10 / 30 seconds (so the next step starts clean).
- Optional shortcut: *Settings › Hotkeys › Draw on the recording (pen on / off)*. It has no default, so it does not take a key from Excel or your browser.
- Your administrator can turn the feature off (`record_annotations`).

**Performance**
- No annotations: no extra cost.
- A step costs about 0.1 ms per frame at 1080p. Large arrows and boxes are drawn as thin strips (a few ms).
- A shape being dragged is redrawn into the video a few times per second, so the frame rate holds.

## Technical release notes
- New `recording.ink`:
  - `InkLayer`: thread-safe, frame coordinates, `from_screen()`, `make()`, `add()`, `add_step()`, `set_draft()`, `undo()`, `clear()`, `views()` with a quantised fade-out, `burn_in` and `drawing` flags;
  - `InkRenderer`: per-item cached BGRA patches, `split_patch()` into 24-row strips trimmed by alpha, `DRAFT_INTERVAL = 80 ms`.
- Shapes are editor `Shape` values. The editor exposes `draw_shape()` and `shape_extent()`.
- `Recorder.ink` is created in `start()` with the rect origin. `EffectRenderer.ink` is composited before cursor highlight, ripples and zoom. Ripples are suppressed while `ink.drawing`.
- Headless / Autopilot:

  ```python
  rec = app.recording.start(rect)
  rec.ink.add_step(rec.ink.from_screen(Point(x, y)))
  ```

- UI:
  - new `ui.ink_overlay.InkOverlay`, excluded from capture, click-through via `platform.win32_window.set_click_through` (extended style only, so the HWND and its exclusion are kept);
  - without `WDA_EXCLUDEFROMCAPTURE`, `burn_in` is off and the overlay itself is recorded;
  - `RecordingBar(ink=)` with the pen button and a tool strip;
  - `RecordingController.toggle_draw()` / `set_ink_tool()`; `escape()` first returns `recording.ink`.
- New hotkey action `record.draw` (unassigned), policy feature `record_annotations`, settings `recording.ink_color`, `recording.ink_fade_seconds`, icon `pen`.
- Tests: `tests/test_ink.py` (model, rendering, strips, throttle, effects, recorder end-to-end), UI tests for drawing, Esc and policy. No new dependencies.
