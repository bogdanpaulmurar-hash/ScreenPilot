# Release 0.9.4 — Scrolling capture: no rows twice in file lists

## User release notes
- **Fixed**: scrolling capture of Explorer (and other lists that highlight the row under the mouse) could repeat a block of rows, mostly near the end of the list, or skip frames in manual mode.

## Technical release notes
- `capture.scrolling.find_shift`: a shift voted by unique rows is also accepted when the rows that differ form at most two short runs (`_hover_only`: the hovered item before and after the scroll, up to `2 * HOVER_BAND` rows each) and at least `HOVER_MIN_MATCH` of the overlap is identical. Before, these frames fell back to the tolerant profile match, which picks wrong offsets on lists whose rows look alike (and prefers the previous step, wrong after the partial last scroll).
- Tests: `FileListScrollingTests` (automatic and manual, several view heights) with an Explorer-like `FileListWindow`; they fail on 0.9.3.

## Checklist (Windows)
- [ ] Explorer folder with ~30 files, automatic scrolling capture of the list: every file once, last file at the bottom.
- [ ] Same in manual mode, scrolling with the wheel while the mouse is on the list.
- [ ] A web page and an Excel sheet still capture as before.
