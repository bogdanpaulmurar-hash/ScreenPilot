# Release 0.9.0 — Backup and restore

## User release notes
- **Settings › Backup**: back up your settings and saved context to a folder you choose (default `Documents\ScreenPilot Backups`).
  - A backup is one file, `ScreenPilot-backup-YYYYMMDD-HHMMSS.zip`, with the settings, the shortcuts, the capture history list with its thumbnails and the procedures still being recorded.
  - Not included: the captures and recordings themselves (they stay in their folder), logs and temporary files.
  - **Automatic**: once a day when ScreenPilot starts (default), at every start, or manual only. It runs in the background about 10 seconds after start-up; a message appears only if it fails.
  - **Copies kept** (default 10): older backups are deleted; safety copies and other files in the folder are not touched.
  - A yellow note warns when the folder is synced by OneDrive, Google Drive or a similar app.
- **Back up now**: in Settings › Backup, in the tray menu, as a shortcut (Settings › Shortcuts › "Back up settings now") and in DevPilot's hub.
- **Restore…**: choose a backup and see what would change (settings, shortcuts, captures added to the history, procedures, paths adapted) before anything is written; *Show details* lists them.
  - Your current state is saved first as `…-before-restore.zip`.
  - Settings and shortcuts are replaced; the history and the procedures are merged (nothing of yours is removed).
  - *Start with Windows* and the backup settings stay as they are on this PC.
  - **Another PC**: folders under another user's profile (`C:\Users\<name>`) point to this PC's profile (can be turned off); captures that are not found are listed and skipped.
  - A file that is not a ScreenPilot backup is refused and nothing changes.

## Technical release notes
- `core.backup` (headless, stdlib `zipfile`): `create_backup()` (atomic temp file, rotation via `rotate()` / `list_backups()`), `read_backup()` (manifest format `screenpilot.backup` v1, unsafe member names ignored), `plan_restore()` → `RestorePlan`, `apply_restore()`, `remap_path()`, `is_due()`, `default_folder()`, `is_cloud_folder()`, `BackupError.message_key`.
- `app.backup`: the running-app layer (live settings and hotkeys, `backup.last`, safety copy, live reload) used by the UI, the CLI and automation.
- `Settings.normalize()`, `Settings.replace()` (listeners hear every changed key), `settings.store.changed_keys()`; `CaptureHistory.reload()`.
- New settings `backup.folder`, `backup.mode` (`daily` / `every_start` / `manual`), `backup.keep`, `backup.last`, `backup.adapt_paths`.
- New action `app.backup_now` (tray, shortcut, `python -m screenpilot action app.backup_now`, `devpilot.tool.json`); `AppController.backup_now()`, `auto_backup()` (worker thread, `backup_done` signal), `restore_backup()`, `confirm_restore()`, `describe_restore()`.
- No new dependency.
- Tests: `tests/test_backup.py` (headless) and `BackupUiTests` in `tests/test_ui.py`.

## Checklist (Windows)
- [ ] Settings › Backup: default folder, "Once a day", 10 copies; Browse… opens the Windows folder picker.
- [ ] Back up now (Settings, tray, DevPilot): a zip appears and "Last backup" updates; the zip has `manifest.json`, `config/`, `data/` and no captures.
- [ ] Restart twice the same day: one automatic backup; "Every start": one per start; "Manual only": none.
- [ ] Copies kept = 3, five backups: the newest 3 remain, other files are untouched.
- [ ] Restore: preview, safety copy, settings/shortcuts back, history and procedures merged.
- [ ] Restore on another PC: paths adapted, missing captures listed.
- [ ] Restore… on a random zip: refused, nothing changes.
