# Release 0.5.2 — Sharper captures and videos

## User release notes

**Capture and editor**
- **Captures look as sharp as on the screen** when Windows scaling is 125 % or 150 %.
  - The editor, *Number steps* and the OCR window showed the image enlarged by the scaling factor, so text looked soft. Now one image pixel is one screen pixel (large captures are still fitted to the window).
  - The quick preview and the *Open editor* picker use sharp thumbnails.
  - The saved file and the clipboard were already full quality (PNG); nothing changes there.

**Recording**
- **Sharper MP4 text and true colours.**
  - Colours are converted the way video players expect (BT.709), so red/blue text and Excel cells no longer look washed out or shifted.
  - *Balanced* quality is now higher (small UI text stays readable). If you never changed the quality, you get the new value automatically.
  - *High* is a bit higher too; *Small file* stays a smaller file.

## Technical release notes
- `capture.geometry.fit_view(image_w, image_h, view_w, view_h, dpr=, margin=)`: pure function, caps the scale at `1 / dpr` and snaps the origin to the physical pixel grid.
- `ui.qt_helpers.fit_target(widget, w, h, margin)` and `sharp_thumbnail(pixmap, size, dpr)`; used by `EditorCanvas.target`, `StepCanvas._target`, the OCR image view, `DragThumbnail` and `EditorPicker`.
- `recording.ffmpeg.record_command`:
  - video always goes through `-filter_complex "[N:v]scale=out_color_matrix=bt709:out_range=tv:flags=lanczos+accurate_rnd+full_chroma_int[v]"` (the two-device audio `amix` is in the same graph);
  - `-colorspace/-color_primaries/-color_trc bt709 -color_range tv` tags;
  - `-thread_queue_size 512` on the raw video input.
- Recording quality default 23 → 20; presets High 17 / Balanced 20 / Small 26.
- Settings schema **3**: `_v2_to_v3` moves `recording.quality` 23 → 20 only when it still had the old default.
- New tests: `tests/test_geometry.py`; command and migration tests extended. No new dependencies.
