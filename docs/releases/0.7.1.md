# Release 0.7.1 — Works with DevPilot

## User release notes

**One ScreenPilot at a time**
- Starting ScreenPilot again (Start menu, DevPilot, a shortcut) no longer shows *"ScreenPilot is already running"*. The running app opens its Capture Hub instead.
- Started with Windows while it already runs: nothing happens. There is no second tray icon and no hotkey-conflict message.

**Actions from outside: DevPilot, shortcuts, scripts**
- `python -m screenpilot action capture.region` runs Region capture in the running app, with the usual preview, history and after-capture actions.
  - If ScreenPilot is not running, it starts and then runs the action.
- Every action of the hotkeys page works, plus `app.show_hub`, `app.settings` and `app.quit`:
  - `capture.delayed --seconds 5`;
  - `app.edit_video --path C:\Videos\demo.mp4`;
  - `python -m screenpilot action --list` shows them all.
- The command-line tools (`capture`, `record`, …) no longer save the settings file when they end, so they never undo a change you just made in the app.

**DevPilot**
- New file `devpilot.tool.json`: DevPilot reads ScreenPilot's options from it. The options are Region, Capture + edit, Window, Video, Screen, Scrolling, Steps, Delayed, GIF, Edit a video, OCR, Procedure, Colour picker, Editor, History, Captures folder, Settings and Open.
- When DevPilot owns the tray icon, ScreenPilot shows none of its own. Its messages appear as small cards in the bottom-right corner, and you can click them like the tray messages.
- When DevPilot owns *start with Windows*, ScreenPilot no longer re-creates its autostart entry. The switch in *Settings › General* is greyed out and explains why.
- Use `%LOCALAPPDATA%\ScreenPilot\venv\Scripts\pythonw.exe` as the interpreter in DevPilot. DevPilot 2.1 fills it in by itself.

## Technical release notes
- New `screenpilot.instance`:
  - `InstanceServer(data_dir, handler)` / `send(data_dir, message)` / `action_message()`;
  - Windows named pipe `\\.\pipe\ScreenPilot-<sha1(data_dir)>`, else a Unix socket in the data folder;
  - HMAC authentication with a random 32-byte `instance.key` in the data folder;
  - the first-pipe-instance flag acts as the lock; a stale Unix socket is replaced;
  - `_stop` wakes `accept()` on shutdown.
- `ui.main`:
  - `startup_command()`; the request is forwarded before Qt or the app is created (the second start no longer saves settings);
  - `gui --action <id> [--seconds n] [--path p]`;
  - `QLockFile` and the "already running" box were removed.
- `AppController`:
  - `remote_command` signal, `accept_remote()` (validates on the listener thread) and `run_remote()` (GUI thread, `trigger(..., from_menu=True)` so the caller's window can close);
  - `REMOTE_EXTRAS`, `remote_actions()`, `tray`, `shutdown(persist=)`.
- New `platform.devpilot` (`managed`, `suppressed`, `owns`). `TrayIcon` falls back to the new `ui.toast.Toast` when hidden.
- `ScreenPilotApp.shutdown(persist=)`. The CLI persists only for `setup`.
- CLI `action [id] [--seconds] [--path] [--list] [--no-start]` and `remote_action_ids()`.
- Tests: `tests/test_instance.py` (forwarding, lock, wrong key, stale socket, stop, errors, concurrency, DevPilot env, manifest ids, startup command, CLI) and UI tests for forwarded actions and the toast. No new dependencies.
