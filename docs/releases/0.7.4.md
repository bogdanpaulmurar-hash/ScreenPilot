# Release 0.7.4 — Recordings survive a killed encoder; the window shows up at once

## User release notes
- **Opening ScreenPilot** from the Start menu, the Desktop or DevPilot always shows the Capture Hub, and it shows right away. The tray icon and the capture bar follow a moment later.
  - *Settings › General › When Windows starts it, stay in the tray* now applies only to starting with Windows. Before, it also hid the window when you opened ScreenPilot yourself, so it looked as if nothing happened.
  - The very first start after an install can still take longer: Windows checks the newly installed files once.
- **When FFmpeg is stopped in the middle of a recording** (for example by security software), the video recorded until then is kept and playable. The message says how many seconds were saved; clicking it shows the file.
- **When Windows refuses to start FFmpeg** ("access denied"), the message says so, and the recording is saved as GIF.
- `record-info` shows why a found FFmpeg cannot be used.
- **Installer**: it closes the running ScreenPilot properly first, however it was started (`screenpilot.exe`, pythonw, DevPilot). Files are no longer replaced under a running copy, which had caused the crashes in the log.

## Technical release notes
- MP4 segments are fragmented, using `-flush_packets 1 -movflags +frag_keyframe+empty_moov+default_base_moof`. Joining segments still writes a regular `+faststart` MP4.
  - Tested: ffmpeg killed with SIGKILL after 12 s still left 10 s playable.
- New `FfmpegSink.salvage()`. It keeps one segment as the output, joins several, or keeps them as `_partN.mp4`.
- `Recorder._fail()` salvages when more than `SALVAGE_AFTER_S` (5 s) were recorded, so the UI's one-time encoder retry covers shorter runs. `recording.failed` carries `partial` and `seconds`.
- `RecordingService.problem` / `ffmpeg_blocked`. `RecordingController` shows `recording.ffmpeg_blocked.*` or `recording.partial_saved`.
- `ui.main`:
  - the hub (or wizard) is shown before the tray and the edge bar, which are created in `QTimer.singleShot(0)`;
  - start-up phases (imports, qt, core, controller, window, tray, edge_bar) are recorded in `app.startup` and logged.
- `install.ps1` / `uninstall.ps1`: `Stop-ScreenPilot` first sends `action app.quit --no-start`, then stops leftovers by venv path or by `-m screenpilot` / `screenpilot(-gui).exe` in the command line.
